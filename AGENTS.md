# CLAUDE.md — Nexcore

## 1. CONTEXTO DEL PROYECTO

Nexcore es una empresa de desarrollo de software, sitios web y soluciones digitales.

Sitio web:
https://nexcoredev.tech

Objetivo principal:
Convertir visitantes en potenciales clientes mostrando que Nexcore puede crear sitios web, sistemas y soluciones digitales modernas, rápidas y profesionales.

El sitio debe transmitir:

- Innovación
- Tecnología
- Confianza
- Profesionalismo
- Cercanía
- Creatividad
- Calidad
- Modernidad

La web NO debe parecer una plantilla genérica de una agencia de marketing.

Debe sentirse como una empresa tecnológica moderna y especializada en crear productos digitales.

---

# 2. OBJETIVO DE DISEÑO

Crear una experiencia visual:

- Moderna
- Innovadora
- Elegante
- Amigable
- Profesional
- Minimalista
- Tecnológica
- Dinámica
- Fácil de entender
- Orientada a conversión

La primera impresión debe comunicar inmediatamente:

"En Nexcore convertimos ideas en soluciones digitales."

El usuario debe entender rápidamente:

1. Qué hace Nexcore.
2. Qué problemas puede solucionar.
3. Qué servicios ofrece.
4. Por qué debería confiar en Nexcore.
5. Cómo puede contactar o solicitar un proyecto.

---

# 3. PRINCIPIOS DE DISEÑO

## 3.1 Menos, pero mejor

No llenar la interfaz con elementos innecesarios.

Priorizar:

- Espacio negativo
- Jerarquía visual
- Tipografía
- Contraste
- Composición
- Animaciones sutiles
- Componentes bien definidos

Cada elemento debe tener una razón.

---

## 3.2 Evitar diseños genéricos

NO utilizar automáticamente:

- Hero genérico con texto a la izquierda y una imagen de laptop a la derecha.
- Gradientes excesivos.
- Fondos con demasiados círculos.
- Ilustraciones genéricas de personas.
- Stock photos innecesarias.
- Cards idénticas repetidas sin propósito.
- Secciones con apariencia de plantilla.
- Exceso de glassmorphism.
- Exceso de sombras.
- Exceso de animaciones.

Buscar composiciones originales.

---

# 4. IDENTIDAD VISUAL

Nexcore debe tener una identidad tecnológica contemporánea.

La estética debe combinar:

Tecnología + Minimalismo + Confianza + Creatividad.

Evitar una estética excesivamente "cyberpunk".

No utilizar:

- Neon exagerado.
- Efectos futuristas excesivos.
- Fondos negros con demasiados brillos.
- Gradientes multicolor sin propósito.

La tecnología debe sentirse sofisticada, no infantil.

---

# 5. PALETA DE COLORES

Usar una paleta principalmente oscura y tecnológica.

Color principal:

#0B0F19

Color secundario:

#111827

Superficie:

#161D2B

Superficie elevada:

#1C2535

Texto principal:

#F8FAFC

Texto secundario:

#94A3B8

Color de acento:

#6366F1

Color de acento secundario:

#8B5CF6

Color positivo:

#22C55E

Usar los colores de acento con moderación.

No convertir toda la interfaz en un degradado.

Los colores deben utilizarse para:

- CTAs
- Links importantes
- Estados
- Elementos destacados
- Detalles visuales
- Interacciones

---

# 6. TIPOGRAFÍA

Priorizar una tipografía moderna y altamente legible.

Preferencias:

- Inter
- Geist
- Manrope
- Plus Jakarta Sans

Usar máximo 1 o 2 familias tipográficas.

Jerarquía recomendada:

H1:
48–72px desktop
36–44px mobile

H2:
36–48px desktop
30–36px mobile

H3:
22–28px

Body:
16–18px

Small:
13–14px

Los headings deben tener personalidad y alto contraste.

No utilizar textos gigantes que ocupen toda la pantalla sin necesidad.

---

# 7. HERO SECTION

El Hero es la sección más importante.

Debe comunicar inmediatamente:

Qué hacemos + beneficio + CTA.

Ejemplo conceptual:

"Construimos soluciones digitales que hacen crecer tu negocio."

Subtexto:

"Sitios web, sistemas y experiencias digitales diseñadas para convertir ideas en productos reales."

CTAs:

"Crear mi proyecto"

"Ver nuestros servicios"

El CTA principal debe destacar visualmente.

---

# 8. HERO VISUAL

No utilizar simplemente una imagen stock.

Crear una representación visual del trabajo tecnológico de Nexcore.

Puede incluir:

- UI de aplicaciones
- Código
- Dashboard
- Ventanas flotantes
- Componentes de interfaz
- Mockups
- Sistemas conectados
- Animaciones
- Métricas
- Arquitecturas visuales

Pero debe mantenerse limpio.

El visual debe reforzar el mensaje, no competir con él.

---

# 9. NAVBAR

La navegación debe ser:

- Minimalista
- Limpia
- Sticky
- Responsive

Elementos sugeridos:

Inicio
Servicios
Proyectos
Nosotros
Contacto

CTA:

"Comenzar proyecto"

En desktop:

- Logo a la izquierda
- Navegación centrada
- CTA a la derecha

En mobile:

- Logo
- Menú hamburguesa

El navbar no debe ocupar demasiado espacio.

---

# 10. ESTRUCTURA DEL SITIO

La página principal puede seguir esta estructura:

1. Navbar
2. Hero
3. Prueba social / métricas
4. Servicios
5. Cómo trabajamos
6. Proyectos / Portfolio
7. Beneficios
8. Tecnologías
9. Testimonios
10. CTA final
11. Footer

No crear todas las secciones automáticamente si no aportan valor.

La página debe sentirse como una historia.

---

# 11. SECCIÓN DE SERVICIOS

Mostrar claramente los principales servicios de Nexcore.

Ejemplos:

### Desarrollo Web

Sitios web modernos, rápidos y optimizados para convertir visitantes en clientes.

### Sistemas Web

Plataformas personalizadas para automatizar procesos y administrar negocios.

### E-commerce

Tiendas online diseñadas para vender productos y facilitar la gestión.

### Aplicaciones / Software

Desarrollo de soluciones digitales personalizadas.

### Automatización

Automatización de procesos para ahorrar tiempo y reducir tareas repetitivas.

Cada servicio debe tener:

- Icono
- Nombre
- Descripción corta
- Beneficio
- Microinteracción

Evitar cards excesivamente grandes.

---

# 12. BENEFICIOS

No limitarse a describir características técnicas.

Comunicar beneficios empresariales.

Ejemplos:

"Más clientes"

"Procesos automatizados"

"Menos trabajo manual"

"Mayor presencia digital"

"Experiencias rápidas"

"Soluciones escalables"

La pregunta que debe responder cada sección es:

"¿Por qué esto le importa al cliente?"

---

# 13. PORTFOLIO

El portfolio debe ser una de las secciones visualmente más fuertes.

Mostrar proyectos reales cuando estén disponibles.

Cada proyecto debe comunicar:

- Problema
- Solución
- Resultado
- Tecnologías utilizadas

Evitar mostrar únicamente:

"Proyecto X — WordPress"

Preferir:

"Transformamos un proceso manual en una plataforma digital."

La imagen/mockup debe tener protagonismo.

Usar layouts asimétricos cuando ayuden a generar interés visual.

---

# 14. SECCIÓN "CÓMO TRABAJAMOS"

Mostrar un proceso simple.

Ejemplo:

01 — Descubrimos

Entendemos tu negocio y objetivos.

02 — Diseñamos

Creamos la experiencia y estructura.

03 — Construimos

Desarrollamos la solución.

04 — Lanzamos

Publicamos y dejamos todo funcionando.

05 — Evolucionamos

Mejoramos el producto con el tiempo.

Utilizar una representación visual interesante.

No limitarse a cinco cards iguales.

---

# 15. TECNOLOGÍAS

Mostrar tecnologías relevantes únicamente.

Ejemplos:

Next.js
React
Node.js
PostgreSQL
Docker
WordPress
Laravel
Tailwind CSS

No mostrar una lista enorme solo para impresionar.

El objetivo es demostrar capacidad técnica sin abrumar al usuario.

---

# 16. CTA

Los llamados a la acción deben ser claros.

Preferencias:

"Crear mi proyecto"
"Cuéntanos tu idea"
"Solicitar propuesta"
"Hablar con Nexcore"

Evitar CTAs genéricos como:

"Click aquí"
"Más información"

El CTA debe explicar qué sucederá.

---

# 17. WHATSAPP

La web puede incluir un botón flotante de WhatsApp.

Debe:

- Ser fácilmente visible.
- No bloquear contenido.
- Tener animación muy sutil.
- Ser accesible en mobile.

No debe convertirse en el elemento visual principal de la página.

---

# 18. ANIMACIONES

Las animaciones deben sentirse premium.

Preferir:

- Fade
- Slide
- Scale pequeño
- Parallax sutil
- Hover
- Reveal al hacer scroll
- Transiciones suaves

Duración aproximada:

200–700ms.

Usar easing suave.

NO utilizar:

- Animaciones constantes.
- Elementos rebotando.
- Texto moviéndose permanentemente.
- Parallax exagerado.
- Animaciones que dificulten la lectura.

Las animaciones deben mejorar la experiencia, no distraer.

---

# 19. MICROINTERACCIONES

Agregar microinteracciones donde tengan sentido.

Ejemplos:

Buttons:

hover → pequeño cambio de escala / brillo / posición.

Cards:

hover → elevación o desplazamiento mínimo.

Links:

hover → transición de color o underline.

Imágenes:

hover → zoom muy pequeño.

Estas interacciones deben sentirse naturales.

---

# 20. RESPONSIVE DESIGN

Mobile First.

La web debe funcionar perfectamente en:

- 320px
- 375px
- 390px
- 414px
- 768px
- 1024px
- 1280px
- 1440px
- 1920px

No diseñar únicamente para desktop y luego "arreglar" mobile.

Cada sección debe revisarse específicamente en mobile.

---

# 21. MOBILE

En mobile:

- Reducir tamaños correctamente.
- Evitar textos gigantes.
- Evitar overflow horizontal.
- Mantener CTAs accesibles.
- Reducir animaciones cuando sea necesario.
- Priorizar velocidad.
- Mantener espacios suficientes.

Nunca sacrificar UX por mantener exactamente el diseño desktop.

---

# 22. ACCESIBILIDAD

Cumplir buenas prácticas de accesibilidad.

Siempre que corresponda:

- HTML semántico.
- Alt text.
- Contraste adecuado.
- Focus states.
- Navegación por teclado.
- Labels en formularios.
- Botones correctamente identificados.
- No depender únicamente del color.

No eliminar outlines de focus sin reemplazarlos.

---

# 23. PERFORMANCE

La web debe ser rápida.

Prioridades:

1. LCP
2. CLS
3. INP
4. Optimización de imágenes
5. Lazy loading
6. Code splitting
7. Minimizar JavaScript innecesario
8. Evitar librerías innecesarias

No agregar una librería solamente para conseguir una animación sencilla.

Preferir CSS cuando sea suficiente.

---

# 24. SEO

Utilizar:

- Un único H1 principal.
- Jerarquía correcta de headings.
- Meta title.
- Meta description.
- Open Graph.
- URLs limpias.
- Alt text.
- Schema cuando sea relevante.
- Contenido útil.

El SEO no debe perjudicar el diseño.

---

# 25. COPYWRITING

El contenido debe ser:

- Claro
- Directo
- Humano
- Profesional
- Orientado a beneficios

Evitar lenguaje corporativo vacío.

NO escribir:

"Somos líderes en soluciones innovadoras de transformación digital."

Preferir:

"Construimos sitios y sistemas que ayudan a tu negocio a trabajar mejor."

Hablar como una empresa tecnológica cercana.

No exagerar promesas.

---

# 26. FORMULARIOS

Los formularios deben ser simples.

Solicitar únicamente información necesaria.

Ejemplo:

Nombre
Empresa
Email / WhatsApp
¿Qué necesitas?

CTA:

"Enviar solicitud"

Después del envío:

Mostrar un estado claro de éxito.

Nunca dejar al usuario preguntándose si el formulario funcionó.

---

# 27. FOOTER

El footer debe incluir:

Logo Nexcore

Descripción breve

Navegación

Servicios

Contacto

Redes sociales cuando corresponda

Copyright

Links legales:

Términos y condiciones
Política de privacidad

Debe mantenerse limpio.

---

# 28. COMPONENTES

Crear componentes reutilizables.

Ejemplos:

Navbar
Button
SectionHeading
ServiceCard
ProjectCard
TestimonialCard
TechnologyBadge
CTASection
Footer
WhatsAppButton

Evitar duplicar código.

Si un componente aparece varias veces, convertirlo en componente reutilizable.

---

# 29. ARQUITECTURA

Mantener el proyecto organizado.

Separar:

- UI
- Components
- Sections
- Data
- Utilities
- Assets

No crear archivos gigantes.

Cada componente debe tener una responsabilidad clara.

---

# 30. CÓDIGO

Código:

- Limpio
- Legible
- Mantenible
- Tipado cuando corresponda
- Reutilizable

Evitar:

- Código duplicado.
- Variables innecesarias.
- Magic numbers.
- Hacks CSS.
- !important salvo casos justificados.
- Dependencias innecesarias.

Antes de instalar una librería:

1. Comprobar si puede resolverse con CSS.
2. Comprobar si ya existe una dependencia equivalente.
3. Evaluar impacto en bundle/performance.

---

# 31. REGLAS DE UI

No crear automáticamente una card para cada cosa.

No todo necesita estar dentro de un rectángulo.

Combinar:

- Texto
- Espacio vacío
- Líneas
- Grid
- Cards
- Mockups
- Tipografía
- Imágenes
- Gradientes sutiles
- Elementos decorativos

Crear ritmo visual.

---

# 32. GRID Y ESPACIADO

Utilizar un sistema consistente de spacing.

Preferir múltiplos de:

4px / 8px.

Container recomendado:

max-width: 1200–1280px.

En pantallas grandes mantener márgenes generosos.

No estirar contenido innecesariamente hasta los extremos.

---

# 33. DISEÑO ASIMÉTRICO

Cuando sea apropiado utilizar layouts asimétricos.

Ejemplos:

- Imagen grande + texto pequeño.
- Cards de diferentes tamaños.
- Grid editorial.
- Elementos parcialmente superpuestos.
- Secciones con diferentes ritmos.

Pero la asimetría nunca debe perjudicar la usabilidad.

---

# 34. EFECTOS VISUALES

Se pueden utilizar:

- Gradientes radiales muy sutiles.
- Glow discreto.
- Noise texture.
- Grid background.
- Blur.
- Glassmorphism moderado.
- Borders con baja opacidad.

Siempre deben tener una función estética clara.

No saturar la interfaz.

---

# 35. DARK MODE

La experiencia principal puede ser dark.

El dark mode debe utilizar diferentes niveles de superficie.

No usar negro absoluto para absolutamente todo.

Ejemplo:

Background:
#0B0F19

Surface:
#111827

Surface elevated:
#161D2B

Esto permite crear profundidad.

---

# 36. IMÁGENES

Priorizar:

- Mockups
- Capturas de proyectos
- UI real
- Fotografías propias
- Gráficos personalizados

Evitar stock photography genérica.

Si se necesita una imagen generada, debe respetar la identidad visual de Nexcore.

---

# 37. REGLA DE CONVERSIÓN

Cada sección debe responder al menos una de estas preguntas:

¿Por qué Nexcore?

¿Qué problema solucionamos?

¿Qué podemos hacer?

¿Cómo trabajamos?

¿Qué hemos construido?

¿Por qué confiar?

¿Cómo puedo comenzar?

Si una sección no responde ninguna, reconsiderar su existencia.

---

# 38. REGLA DE JERARQUÍA VISUAL

Cada pantalla debe tener un orden visual claro.

El usuario debería poder identificar rápidamente:

1. Qué es esto.
2. Qué debería leer.
3. Qué debería hacer.

No crear múltiples elementos compitiendo por atención.

El CTA principal debe ser evidente.

---

# 39. REGLA DE ORIGINALIDAD

Antes de implementar una sección, preguntarse:

"¿Esto parece una plantilla de agencia?"

Si la respuesta es sí:

Buscar una composición más original.

Nexcore debe diferenciarse visualmente de:

- Plantillas de WordPress.
- Landing pages genéricas.
- Agencias tradicionales.
- Sitios SaaS clonados.

---

# 40. REGLA DE CONSISTENCIA

Todos los elementos deben pertenecer al mismo sistema visual.

Mantener consistencia en:

- Border radius
- Shadows
- Typography
- Colors
- Spacing
- Buttons
- Animations
- Icons
- Cards

No cambiar el estilo arbitrariamente entre secciones.

---

# 41. ICONOS

Preferir:

Lucide
Phosphor
Heroicons

No mezclar múltiples familias de iconos.

Los iconos deben ser simples y consistentes.

---

# 42. NO HACER

Nunca:

- Crear un diseño genérico sin analizar el objetivo.
- Llenar espacios por llenar.
- Usar 10 colores diferentes.
- Usar demasiados gradientes.
- Usar demasiadas cards.
- Usar animaciones excesivas.
- Usar imágenes stock sin necesidad.
- Crear componentes gigantes.
- Instalar dependencias innecesarias.
- Ignorar mobile.
- Ignorar accesibilidad.
- Ignorar performance.
- Cambiar la identidad visual entre páginas.

---

# 43. PROCESO ANTES DE IMPLEMENTAR

Antes de escribir código para una nueva sección:

1. Entender el objetivo de la sección.
2. Determinar qué debe percibir el usuario.
3. Definir jerarquía visual.
4. Definir contenido.
5. Definir layout.
6. Definir interacción.
7. Implementar.
8. Revisar responsive.
9. Revisar accesibilidad.
10. Revisar performance.
11. Revisar consistencia con el resto del sitio.

---

# 44. AUTONOMÍA DE CLAUDE

Claude puede tomar decisiones de diseño cuando mejoren:

- UX
- Conversión
- Legibilidad
- Estética
- Performance

No preguntar por cada pequeño detalle.

Tomar decisiones razonables y coherentes con esta guía.

Sin embargo, antes de realizar cambios arquitectónicos importantes o introducir nuevas tecnologías, evaluar primero el impacto.

---

# 45. CRITERIO FINAL

El resultado final debe sentirse como:

"Una empresa tecnológica pequeña pero ambiciosa que sabe construir productos digitales."

No como:

"Una plantilla de agencia comprada en Internet."

La web debe generar tres sensaciones:

1. "Se ve profesional."
2. "Saben lo que hacen."
3. "Quiero hablar con ellos."

Cada decisión de diseño debe acercarnos a esas tres sensaciones.
